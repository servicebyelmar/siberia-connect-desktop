# Тесты Windows-клиента для CI

Запускаются job `test` в `.github/workflows/build.yml`; job `build` (он же публикует релиз) имеет `needs: test`.

- `run-selftests.ps1 -Exe <SiberiaConnect.exe> -Work <каталог>` — три прогона собранного exe без GUI, VPN, боевого API и системных изменений:
  1. `--selftest` без `SC_INSTANCE`: конфиги движков, резервная копия, прежние имена мьютекса/события и путь профиля;
  2. `--selftest` с `SC_INSTANCE`: суффиксы имён и профиля, запреты режима экземпляра;
  3. `--selftest-api`: разбор сохранённого ответа `nodes/rank` (`fixtures/rank-ok.json`, SHA256 записанного ответа) и сбои рейтинга на локальном сервере 127.0.0.1 (500, не JSON, пустое тело, `ok=false`, пустые `nodes`, молчащий сервер, оборванное тело, закрытый порт, нет токена).
  4. `--selftest-telemetry`: чистая логика фоновой телеметрии (`TelemetryGate`) — фильтр ложных срабатываний (нет обычного интернета, «Отключить», 10 с после сна, дедуп 10 мин) и очистка лога от секретов; без сети.
- Запрос к боевому API — только вручную перед релизом.
- Сценарий 4 (физический разрыв линка) — только стенд: `STAND-4.md`.
- `SC_API_BASE` действует только в режиме экземпляра и только для loopback.
